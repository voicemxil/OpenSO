# Per-RID Client Distribution Manifest

This document defines `openso-manifest.json`, the platform-aware index the OpenSO Launcher uses to
download and update the game client. It is the contract between release CI (which generates the manifest)
and the Launcher (which consumes it).

> **This is not the in-game update manifest.** `OpenSO-client-win-x64.manifest.json` (and the
> `fso_updates` table / `GET /userapi/update` it feeds) is a separate, **Windows-only** system: the
> in-game updater's delta chain of file diffs. See [Updates.md](./Updates.md). `openso-manifest.json`
> described here is the cross-platform distribution index and lives entirely in GitHub release assets.

## Where it lives

Every release publishes `openso-manifest.json` as a release asset, next to the client zips. Stable URLs:

- Specific release: `https://github.com/voicemxil/OpenSO/releases/download/<version>/openso-manifest.json`
- Latest release: `https://github.com/voicemxil/OpenSO/releases/latest/download/openso-manifest.json`

It is generated by `.github/scripts/gen-manifest.py`, invoked from the `client-manifest` job in
`release.yml` and (on re-generation) from `delta-backfill.yml`.

## Schema

```json
{
  "schemaVersion": 1,
  "version": "v0.2.1",
  "clients": {
    "win-x64":   { "full": { "url": "...", "sha256": "..." }, "deltas": [{ "from": "v0.2.0", "url": "...", "sha256": "..." }] },
    "linux-x64": { "full": { "url": "...", "sha256": "..." } },
    "osx-x64":   { "full": { "url": "...", "sha256": "..." } },
    "osx-arm64": { "full": { "url": "...", "sha256": "..." } }
  }
}
```

| Field | Meaning |
| --- | --- |
| `schemaVersion` | Manifest format version. Currently `1`. Consumers must reject a version they don't understand. |
| `version` | The release this manifest describes (the git tag / `version.txt`, e.g. `v0.2.1`). |
| `clients` | Map of **exact** runtime identifier (RID) to that platform's packages. |
| `clients.<rid>.full` | **Mandatory.** The complete self-contained client zip for the RID. `url` + `sha256`. |
| `clients.<rid>.deltas` | **Optional.** Incremental patches, each `{ from, url, sha256 }`, where `from` is the base `version`. Windows-only for now. |
| `*.sha256` | Lowercase hex SHA-256 of the asset, computed in CI. Consumers must verify every download against it. |

### Rules

- **Only RIDs the release actually built are present.** A release that skips a platform simply omits it.
- **Exact RID match, no fallback.** A consumer resolves its own RID (`win-x64`, `linux-x64`, `osx-x64`,
  `osx-arm64`) and looks it up verbatim. A missing RID is a clear error — never substitute another
  platform's build (that is the win-x64-zip-for-everyone bug this manifest exists to prevent).
- **Full package is always usable on its own.** `deltas` are an optimization; a consumer may always ignore
  them and download `full`.
- **Hash-verify everything.** Reject any download whose SHA-256 doesn't match the manifest.

The RID a client reports is produced by `FSOEnvironment.RID` (see `TSOClient/tso.common/FSOEnvironment.cs`),
normalized to exactly these strings.

## Generation

`.github/scripts/gen-manifest.py <version> <prev-or-empty> <artifact-dir> <owner/repo> <out-file>`:

1. Scans `<artifact-dir>` (the release's downloaded `OpenSO-client-*` assets) for `OpenSO-client-<rid>.zip`.
2. Computes SHA-256 for each present full zip and emits a `full` entry with a `releases/download/<version>/...` URL.
3. For Windows, if `OpenSO-client-win-x64.incremental.zip` is present and a previous version was resolved,
   adds a single `deltas` entry `{ from: <prev>, ... }`.
4. Fails (non-zero) rather than writing an empty manifest if no client zips are found.

## Relationship to the login compatibility response

The game client's login (`cityselector/app/InitialConnectServlet`) returns a compatibility response
(`User-Authorized`) carrying the target `FSO-Version` / `FSO-Branch` and an `FSO-UpdateUrl`. That
`FSO-UpdateUrl` is the **Windows in-game patch payload** and is only returned to Windows clients — the
client now sends its RID (`?rid=<rid>`) at login, and the server returns **no** package URL to non-Windows
clients. Those clients rely on the Launcher and this manifest to update to the advertised version instead.
Clients that send no RID (legacy) are treated as Windows to preserve the existing in-game flow.
